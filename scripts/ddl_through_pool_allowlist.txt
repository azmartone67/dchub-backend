# ddl_through_pool_allowlist.txt — the DDL that has never actually run.
#
# Every line below is a function that issues CREATE TABLE / CREATE INDEX /
# ALTER TABLE on a cursor obtained from db_utils, whose PGCursorWrapper drops
# those statements on the floor whenever SKIP_DDL is set — and SKIP_DDL
# DEFAULTS TO '1' (db_utils.py:13) and is absent from prod config. So the DDL
# on these lines has, to the best of our knowledge, never executed in
# production. Where the table exists anyway, a migration or an older
# pre-SKIP_DDL deploy created it; where it does not, the module's first INSERT
# has been failing silently ever since.
#
# ★ THIS IS A FREEZE, NOT AN AMNESTY. The list exists so
# scripts/check_ddl_through_pool.py could go in the day it was written rather
# than behind a 60-function migration. It is only ever meant to SHRINK. Adding
# a line means shipping a table-create that will not create the table.
#
# ★ DO NOT ADD A LINE TO MAKE CI GREEN. That is the exact move that produced
# every entry below: a lazy CREATE that looked like it worked. If the guard
# fires on new code, open a direct psycopg2 connection for the DDL (see
# routes/email_suppression._ensure_table) or move it to a migration.
#
# To remove a line: fix the function, then delete the line. The script reports
# entries with no matching offence so a fixed one cannot sit here forever.
#
# Format: <path>::<qualified function name>   # <n> DDL statement(s)
#
# ── 2026-08-04: the live audit ran. 49 EXISTS / 5 MISSING / 5 PARTIAL ────
#
# routes/ddl_audit.py asked the production database whether each frozen
# CREATE's table exists. FORTY-NINE of 59 already exist — created by a
# migration or by a deploy predating SKIP_DDL — so their lazy CREATE is dead
# weight and converting it would have been ~140 tables of churn for nothing.
# That measurement is the reason this list was frozen instead of "fixed".
#
# Of the five MISSING, only TWO were reachable code, and both are now fixed and
# gone from this list (main._eia_task_persist, observability_routes.anomalies).
# The other three are recorded here so nobody re-derives the disposition:
#
#   ai_agent_discovery.py::init_tracking_db  ->  ai_access_log
#       DEAD. Its register_discovery_routes() is never called — main.py:8637
#       imports the SAME-NAMED function from ai_discovery_routes.py instead.
#       ai_access_log is written and read only inside this module. main imports
#       exactly one thing from it (identify_ai_platform, a pure function).
#       Creating the table would produce an empty table nobody reads.
#
#   free_tier_limiter.py::_init_tables  ->  free_tier_usage
#       DEAD. main.py does not import this module at all; the live free-tier
#       gate is free_tier_gate.py + util/tier_gate.py + tier_registry.py.
#       ★ A missing free_tier_usage does NOT mean quotas are unenforced — the
#       enforcing path is elsewhere and has its own storage. Same shape as
#       mcp_tier_config.py: written for a real problem, never wired.
#
#   self_learning_discovery.py::SelfLearningDiscovery._init_db
#       -> discovered_sources, discovery_patterns, learned_keywords
#       LEGACY, and the call was ALREADY made: routes/autopilot_routes.py:381
#       reports "legacy engine — discovered_sources table never provisioned"
#       rather than provisioning it. Overriding that here would be reversing
#       someone's decision by accident.
#
# The 5 PARTIAL entries are functions where some tables exist and some do not;
